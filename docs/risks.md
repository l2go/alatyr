# Risk register

Reviewed at the close of each milestone. Last review: 2026-10-06, close of M1. Likelihood and impact are Low, Medium, or High. Status is Open, Mitigated, or Closed.

| ID | Risk | Likelihood | Impact | Mitigation | Status |
|---|---|---|---|---|---|
| R-1 | The Netty core was adopted without a comparison ([ADR-0005](adr/0005-netty-network-core.md)). Cipher ordering, back-pressure, or disconnect behavior may differ from the old core | Medium | High | Conformance tests on fixed vectors, an end-to-end smoke test in CI, a load of many sessions against the running image in CI, and conditions for reopening the decision in the record | Open |
| R-2 | The Arch Linux base is a rolling release, so an unpinned build can change without notice | High | Medium | Base pinned by dated tag and digest, packages from a dated Arch Linux Archive snapshot, JDK pinned as a separate archive ([ADR-0002](adr/0002-linux-image-delivered-with-compose.md)) | Open |
| R-3 | The official Arch image is `linux/amd64` only. No arm64 image is published | Medium | Medium | Revisit if an official arm64 image appears | Open |
| R-4 | Published ports are reached through the Docker gateway, so the server sees that address and per-address limits collapse to one address | High | Medium | Not a claimed remote setup. A host-network profile exists for the Linux stack in CI | Open |
| R-5 | Docker's default security profile blocks `io_uring`, so the vision's `io_uring` benefit is unavailable by default | High | Low | Default transport is epoll; `io_uring` is an opt-in with a custom profile | Mitigated |
| R-6 | Windows and macOS are not checked and are not a claimed way to run the server | High | Low | GitHub Actions on Linux is the run | Accepted |
| R-7 | M2 is large because the work is not sliced into releases | Medium | Medium | Packages with green CI after each, and a report after each large group of packages | Open |
| R-8 | The data-access seam grows beyond the three chosen domains | Medium | Medium | A test lists the 109 classes that reach the database directly and fails for a new one, so the count only falls; the seam stays limited by [ADR-0006](adr/0006-data-access-layer.md) | Mitigated |
| R-9 | Concurrency defects in shared state: maps and lists in clan, boss, event, and login code, the counter of announced connections, the skills of a non-player character, and the reuse list of a player | Medium | Medium | The counter, the failed-login count and the skill map are tested from several threads (a lost update was observed, 15998 of 16000 failed logins counted) and fixed. The clan, boss, tomb, and event collections are concurrent now, and the damage to a hideout boss and the reuse packet are made atomic. Loops that removed from the collection they walked, which Javolution tolerated and the JDK does not, were found in the quests, the clans, the castles, the skill targets, and the death notification; they walk copies and a source test fails the build on a new one. The queue of the packets of a client, the Olympiad registers, the party matching, and the fort siege lists are made safe for several threads. The packets of one login client run in order, the disconnect of a world client runs behind its own packets, and the shutdown closes the listening port before it saves. Items are still written by a queue outside the player transaction, so a crash can split a player row from its items ([#161](https://github.com/l2go/l2jfree/issues/161)) | Open |
| R-10 | One maintainer and one account, with manual merge, so work stops when that person is unavailable | Medium | High | Decisions, runbooks, and reports are written so another person can continue; the ruleset and checks do not depend on the person | Open |
| R-11 | Supply chain: images, base, and dependencies change over time | Medium | High | Digest pins, SBOM, signature, attestations, and a vulnerability scan in the pipeline. The pipeline verifies the signature, the provenance, and the SBOM after every publication, scans the image on every merge and daily, and the release workflow scans again before it tags. GitHub Actions are pinned by commit, and Dependabot updates those pins | Mitigated |
| R-12 | Documentation grows long and repetitive | Medium | Low | One page per decision record, tables in reports, retired documents marked in `docs/index.md` and moved to an archive later | Open |
| R-13 | A container package inherits the visibility of the repository, so `edge` was public while the policy asked for a private package until the release | High | Low | The policy is amended ([ADR-0007](adr/0007-release-policy.md)): one package cannot hide `edge` and publish a release tag, so the package stays public | Closed |
| R-14 | The SQL of the game server, about 600 statements in 131 files by the first estimate (the check counts 688 constant statements), had to move to the accepted schema, and none of it can be run on a workstation | High | High | A check prepares every statement of the compiled server against the real schema in CI: 688 statements prepare, none fails. A second check compares every setter and getter of the code with the type PostgreSQL gives the parameter or the column, and found four defects when it first ran. Repository tests cover what the statements do. Statements built at run time must be listed with a reason | Mitigated |
| R-15 | Code scanning reports the login credential block: a 1024-bit RSA key and RSA without padding. The Lineage II client protocol fixes both, so the server cannot change them without breaking every client | High | Low | The three alerts are dismissed as "won't fix" with that reason. The login port should not be exposed to untrusted networks without a filter, and the threat model in M3 covers it | Accepted |
| R-16 | One process holds both modules, so a fault in the world (a deadlock, an out-of-memory error) stops the login too, and a compromise of one module reaches the memory of the other | Medium | Medium | The roles keep the databases apart (ADR-0009) and the architecture rules keep the code apart (ADR-0003); the process exits non-zero when the start fails and restarts under the compose policy. Isolation inside the process is not claimed | Accepted |
